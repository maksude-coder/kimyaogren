# ADR-004: Preserve kimyaogren.com WordPress URLs

## Status
Accepted — PM decision, 25.09.2026 (Sprint 2.2 planning)

## Context
kimyaogren.com currently runs WordPress with 302 chemistry posts at `https://kimyaogren.com/{slug}/`, 1,361 inline images under `/wp-content/uploads/…`, and grade category archives at `/category/{9..12}-sinif-konulari/`. These URLs carry search ranking and external backlinks. The Laravel application will replace WordPress on the same domain.

The Content domain design (`dd-theory-articles.md` v1.0) makes an article's `slug` unique **per topic**, which cannot reproduce WordPress's single global URL namespace.

## Decision
1. **Articles are served at their exact WordPress URL** `/{legacy_slug}/` (trailing slash, as WordPress canonicalises). `/{legacy_slug}` without the slash 301-redirects to the slashed form, exactly as WordPress does today. A new, globally unique, nullable `theory_articles.legacy_slug` column holds it; `slug` keeps its per-topic meaning.
2. **Images are downloaded** and served statically from the same path `public/wp-content/uploads/…`, so embedded and external image links keep working after WordPress is switched off. Stored HTML references them root-relative (`/wp-content/uploads/…`).
3. **Category archives** `/category/{n}-sinif-konulari/` 301-redirect to the grade page of the curriculum browser. Tag archives (`/tag/…`, 1,392 SEO tags) 301-redirect to `/mufredat`.
4. Legacy handling lives in the router's **fallback** route, so it can never shadow application routes (`/admin`, `/mufredat`, …).
5. Apache's default Laravel "redirect trailing slashes" rule is removed from `public/.htaccess`, otherwise it would 301 every legacy URL away from its canonical form.

## Consequences
- Zero broken links, no ranking loss from URL changes.
- Article URLs are flat and not curriculum-shaped; the curriculum browser links to them. New (non-imported) articles will get a `legacy_slug`-style public slug too unless a later ADR introduces a curriculum-shaped URL for them.
- `public/wp-content/` is generated by the importer and git-ignored; production deploys must run the import (or copy the folder).
