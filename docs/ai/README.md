# AI Onboarding Documentation

## Purpose

This documentation ensures that **any AI coding assistant** (OpenAI Codex, ChatGPT Codex, Claude Code, GitHub Copilot Agent, Gemini CLI, or future AI tools) can join the KimyaÖğren project at any time and immediately understand:

- How the project is managed
- How development should be performed
- What standards and conventions to follow
- What the AI's role and boundaries are

## Reading Order

**Mandatory sequence** - read in this exact order:

1. [01-role-definition.md](01-role-definition.md) - Understand your role and boundaries
2. [02-project-brief.md](02-project-brief.md) - Understand the project goals and philosophy
3. [03-development-rules.md](03-development-rules.md) - Mandatory coding and process rules
4. [04-coding-standards.md](04-coding-standards.md) - Naming, clean code, PHPDoc, enums
5. [05-filament-standards.md](05-filament-standards.md) - Filament-specific conventions
6. [06-database-standards.md](06-database-standards.md) - Migration and database conventions
7. [07-testing-standards.md](07-testing-standards.md) - Testing philosophy and practices
8. [08-git-strategy.md](08-git-strategy.md) - Git workflow and commit conventions
9. [09-task-workflow.md](09-task-workflow.md) - How to execute individual tasks
10. [10-sprint-workflow.md](10-sprint-workflow.md) - How sprints are planned and executed

## How to Use These Documents

### Before Starting Any Task

1. Read **all 10 documents** in order (if joining the project for the first time)
2. Re-read documents relevant to the current task
3. Ask the Project Manager if anything is unclear

### During Task Execution

- Reference specific documents when making implementation decisions
- Follow the workflow in [09-task-workflow.md](09-task-workflow.md) step by step
- Apply conventions from [03-development-rules.md](03-development-rules.md) and [04-coding-standards.md](04-coding-standards.md)

### After Completing a Task

- Update documentation if you changed behavior or conventions
- Follow [08-git-strategy.md](08-git-strategy.md) for commits
- Request review per [09-task-workflow.md](09-task-workflow.md)

## Maintenance

- This documentation lives in version control with the project
- Update when processes change
- Keep cross-references accurate
- Avoid duplication - reference other documents instead
